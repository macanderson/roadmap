Guidance

Build order

Build both at once after a short serial start. Do not finish the steering repo first.

  1. MCP Studio needs five things from the steering lanes.

    The contract (S0) before it starts, the pull request path (S3) and the checks (S4) before its PR and check lanes finish, and publishing (S5) and the Cedar evaluator (S12) before serving (M15). Its importers, compiler, executor, relay, credentials, and local servers are code that needs none of the steering repo.

  2. Steering first would idle MCP Studio.

    Fourteen MCP Studio lanes would wait a whole wave for no reason, and tools/servers/ is where most of a workspace's reviewed configuration will live, so the steering repo's first real content is MCP servers anyway.

  3. The contract is the risk, so it goes alone.

    A wrong name in S0 or M0 costs every lane after it. Those two run one after the other, before any wave starts, and every lane stops and reports a wrong contract instead of working around it.

  4. One design lane covers both.

    U1 puts the steering repo and MCP Studio into mockups/v3, so Mac reviews the whole experience once. S7 and M9 then build the screens from the merged mockup.

  5. The critical path starts first.

    In wave 1, start S1, S3, S4, S5, S12, M4, M6, M7, M13, and M14 before the rest. They gate wave 2 and the live tests.

Proposed. At most 8 lane agents at once, a number Mac can change. Wave 1 alone has 23 lanes.
